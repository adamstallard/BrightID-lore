# BrightID-lore

Curated conventions for the BrightID project — what the team has learned, as opposed to
what happened. Entries are markdown with frontmatter under `entries/`, each carrying the
conditions under which it applies and provenance back to where it came from.

Entries arrive as pull requests. To review one:

- **Delete a file** to reject that entry. Rejection is permanent.
- **Edit a file** to fix wording, conditions, or scope.
- **Merge** to accept everything still present.
- **Close without merging** to defer — nothing is rejected.

Produced and maintained with [igor](https://github.com/adamstallard/igor).
